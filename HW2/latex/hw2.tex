\section{The Questions (65 points)}
\begin{enumerate}
  \item Scan by the book. \textbf{(20 points)}\label{q:scan}\\
    In the \hrefc{https://www.students.cs.ubc.ca/~cs-418/2025-1/lecture/09-17/slides.pdf}{September 17}
    lecture, we implemented \code{reduce} using the bottom-up approach presented in the
    Lin \& Snyder text.
    The template file, \erltemplate{} has the \code{create/2} and \code{reduce/3}
    functions from that lecture.
    For this question, you will implement \code{scan}.
    \begin{enumerate}
      \item \textbf{(10 points)} Implement \code{scan(ProcInfo, CombineFun, AccIn, Value)} where
	\code{scan} is called by the worker processes:
	\begin{description}
	  \item{\code{ProcInfo}} is the \code{ProcInfo} for the process calling \code{scan};
	  \item{\code{CombineFun(Left, Right)}} is the function for combining values from
	    the left and right subtrees of the current node.
	  \item{\code{AccIn}} is the initial value for the accumulation.
	    All workers should call \code{scan} with the same value for \code{AccIn}.
	  \item{\code{Value}} is the value for the scan for this worker.
	\end{description}
	\code{scan} implements a ``exclusive'' scan: the value returned by \code{scan}
	  is the value obtained by combining all values prior to the current worker.
	  In other words, it doesn't include the value from the current worker.
	  For example, if\\
	  \rule{1.5em}{0ex}\code{CombineFun(Left, Right) -> Left + Right end,}\\
	  and we have 8 workers processes whose values for the scan are the elements of\\
	  \rule{1.5em}{0ex}\code{[1,2,3,4,5,6,7,8]},\\
	  then the values returned by \code{scan(ProcInfo, CombineFun, AccIn, Value)} will be\\
	  \rule{1.5em}{0ex}\code{[0,1,3,6,10,15,21,28]}.\\
	  Note that you can get the effect of an inclusive scan that includes the
	  value from the current worker by applying\\
	  \rule{1.5em}{0ex}\code{CombineFun(ValueFromScan, Value)}\\
	  We can't necessarily get the value for an exclusive scan from an
	  inclusive scan; that only works if \code{CombineFun} is invertible.
	\par  See the test case in \code{hw2\_tests.erl} for an executable example.
	\par My implementation uses a \code{scan/5} that is based on the code from
          \code{hw2:reduce/4} with an extra parameter for \code{AccIn}.
	  You can solve this problem ``easily'' by copying the code from \code{reduce/4},
	  adding a \code{AccIn} parameter, and making the changes to convert a reduce to
	  a scan.  Then, make \code{scan/4} call your \code{scan/5} just like \code{reduce/3}
	  calls \code{reduce/4}.  You can probably find a harder way to solve the problem,
	  but we may take off points if you make the code excessively complicated.
      \item \textbf{(5 points)} Add a test case to \code{hw2\_tests.erl}.
	Use a function for \code{CombineFun} that is both associative and commutative
	and not a test-case example from \testtemplate{}.
	Clearly state in your comments that this is a test case for a function that
	is associative and commutative.
      \item \textbf{(5 points)} Add a test case to \code{hw2\_tests.erl}.  Use a function
	for \code{CombineFun} that is associative but not commutative
	and is not a test-case example from \testtemplate{}.
	Clearly state in your comments that this is a test case for a function that
	is associative but not commutative.
    \end{enumerate}

  \item Help find my moose. \textbf{(25 points)} \label{q:moose}\\
    The moose that was in my refrigerator for
    \hrefc{https://www.students.cs.ubc.ca/~cs-418/2024-2/pika/2/pika2.erl}{PIKA 2} has escaped!
    Please help me find the moose.
    \par
    In a bit more detail, let \code{WorkerTree} be a tree of processes created by \code{wtree:create/1}.
    Let \code{Key} be the key for a list that is distributed across the workers of \code{WorkerTree}.
    In other words,\\
    \rule{1.5em}{0ex}\code{lists:append(wtree:retrieve(WorkerTree, Key))}\\
    returns this list.
    How many times does the string \code{"moose"} occur in this list?
    \par
    The function \code{hw2:moose\_ref(WorkerTree, Key)} is a sequential implementation
    that retrieves the list associated with \code{Key} as described above and returns
    the number of occurrences of \code{"moose"} in that list.
    For this problem, you will write a parallel version using \code{wtree:reduce}.

    \begin{enumerate}
      \item (\textbf{5 points})
	Include in the \code{hw2.erl} file that you submit, a comment (probably 5 to 10 lines)
	a high level description of your implementation:
	\begin{itemize}
	  \item Which of the patterns for reduce from the
	    \hrefc{https://www.students.cs.ubc.ca/~cs-418/2024-1/lecture/09-13/slides.pdf}{September 13 lecture}
	    does your design use?
	    If your design is a different pattern, please explain.
	  \item Describe the ``type'' of the value returned by your \code{Leaf} function,
	    and used as the arguments and return type of your \code{Combine} function.  For
	    example, if it's a list, say that it's a list and describe the type of the elements.
	    If its a tuple, say it's a tuple, and describe the types of the elements.
	  \item Is there anything else another programmer would want to know to understand
	    your implementation.
	\end{itemize}
	This description should be a fairly high-level description of the design.
	Don't write a line-by-line English approximation of what your code does;
	you may assume that we can read Erlang code.

      \item (\textbf{5 points})
	Implement the leaf function, \code{hw2:moose\_leaf(ProcState, Key)}.

      \item (\textbf{5 points})
	Implement the combine function, \code{hw2:moose\_combine(Left, Right)}.

      \item (\textbf{5 points})
	Implement the top-level function, \code{hw2:moose\_par(WorkerTree, Key)}.
	If \code{WorkerTree} is a worker tree, and \code{Key} is a valid key for
	a list distributed across the workers of \code{WorkerTree}, then\\
	\rule{1.5em}{0ex}\code{hw2:moose\_par(WorkerTree, Key) == hw2:moose\_seq(WorkerTree, Key)}\\
	should evaluate to \code{true}.

      \item (\textbf{5 points})
	Add at least three test cases to each of
	\code{hw2\_tests:moose\_leaf\_test()},\\
	\code{hw2\_tests:moose\_combine\_test()}, and
	\code{hw2\_tests:moose\_par\_test()}.

      \item[\textbf{Notes:}]
	\begin{itemize}
	  \item Be careful about cases where the string \code{"moose"} is spread across

\section{Why?}\label{sec:why}
  \begin{description}
    \item{\textbf{Question~\ref{q:scan}}}: Implementing scan is a good exercise to take
      the ``magic'' out of the algorithm.\\
      \textbf{Note}: it was brought to my attention that the
      file names for my PDF uploads to Canvas could be more descriptive.  One is Chapter 5
      of the Lin \& Snyder book.  The other is my introduction to their Peril-L notation.
      If you are finding their notation to be cryptic and you haven't read my introduction,
      you probably want to download that file as well.

    \item{\textbf{Question~\ref{q:moose}}}: 
      An example of the \code{\tuple{Left, Overall, Right}} pattern for reduce and scan.

    \item{\textbf{Question~\ref{q:queue}}}: 
      Monte Carlo simulations, i.e.\ randomized simulations are very widely used.
      They are also an example of an ``embarrassingly parallel'' problem.
      Because each of the simulation runs is supposed to be independent of the others,
      many processors can work each on their own set of simulations.
      We need to combine these results at the end, typically creating some kind of summary.
      This combination of the results is often an example of reduce, it is definitely is
      a reduce for the problem posed here.\\
      Simulating queues will help us better understand the routing networks used in messaging
      passing machines.
  \end{description}
