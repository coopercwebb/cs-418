  \item \textbf{Rabin-Miller primality testing} (30 points):\label{q:rabin-miller}\\
    The Rabin-Miller algorithm is a cool algorithm, it is widely used (e.g.\ for generating RSA keys),
    and I'll use it to create ``embarrassingly parallel'' problem for Question~\ref{q:par}.
    This problem comes with a two-page introduction -- I've tried to keep the number theory informal
    and simple, but give hopefully give you enough understanding of the algorithm to appreciate it
    help you when debugging your implementation.

    \textbf{Motivation:} Sometimes, we want to find some fairly large prime numbers.
    For example, the RSA-2048 encryption uses a public key that is the product of
    two prime numbers, where the product should be a 2048 bit integer.
    Thus, each the primes should be roughly 1024 bit integers, or around $10^{308}$.
    How do we find primes with 300 or more digits?
    \par
    The good news is that for numbers near a large integer, $N$, the fraction of
    such integers that are prime is roughly $1/\log(N)$, where $\log$ is the
    natural logarithm.
    See the \hrefc{https://en.wikipedia.org/wiki/Prime_number_theorem}{Prime Number Theorem}
    if you want the details.
    To find a random prime around $10^{J}$ we just need, on average, to try $\log(10^J) \approx 2.3J$ numbers.
    Because we don't need to test even numbers, we can reduce that to half as many, i.e.\ $1.15J$,
    and with further ``tricks'', we could reduce the constant factor even more.
    \par
    Given a large, odd number, $Q$, how can we determine if it's prime?
    Testing all factors up to $Q$ is clearly impractical.
    We only need to test factors up to $\sqrt{Q}$, but if we are looking for prime numbers
    around $10^{308}$ we still need to try $10^{154}$ possible factors for a brute force approach.
    We need something better, and for this problem, we'll use the Rabin-Miller algorithm.
    I'll sketch the ideas behind the algorithm here, and I'll try to keep the number-theory
    fairly informal.
    \par
    The Rabin-Miller primality test is a randomized algorithm.
    There are three main ideas behind the algorithm:
    \begin{description}
      \item{\textbf{Fermat's Little Theorem:}}
	\textit{If $P$ is a prime and $A$ is an integer that is not a multiple of $P$,
	then $A^{P-1} \bmod P = 1$.}\\
	See Appendix~\ref{sec:flt} for a proof and some examples.
      \item{\textbf{The Square Root of 1:}}
	\textit{If $P$ is a prime and $A$ is an integer such that $A*A \bmod P = 1$,
	then either $A \bmod P = 1$ or $A \bmod P = P-1$.}\\
	See Appendix~\ref{sec:sqrt} for a proof and some examples.
      \item{\textbf{Randomized computation:}}
	Fermat's Little Theorem and the observation about squares mod $P$ can be used
	to show that an alleged prime, $Q$ is composite, but can't prove that $Q$ is prime.
	The breakthrough that Rabin and Miller made is they combined these two in a way
	such that the probability that a composite number $Q$ passes both tests for a randomly
	chosen $A$ is at most $\frac{1}{4}$.
	If we choose $K$ different values of $A$ independently, then the probability of $Q$
	passing all $K$ trials is at most $4^{-K}$.
	\par
	For example, if \code{K=50},
	then the probability of incorrectly declaring \code{Q} to be prime is at most
	$4^{-50} \approx 7.9 \times 10^{-31}$.   In other words, if we found one alleged prime
	per nanosecond using the Rabin-Miller test, we'd expect to have a non-prime slip through
	about once every 40 trillion years -- about 300 times the age of the universe.
	If that's not good enough for you,
	just choose $K$ large enough to meet your high standards.
    \end{description}
    \begin{figure}
      \begin{description}
	\item{1.} Let \code{Q} be the number whose primality we wish to test.
	  \code{Q} must be a positive, odd integer.
	  Let \code{K} be a positive integer.
	\item{2.} Find \code{D} and \code{S} such that \code{D} is odd and
	  $\code{Q-1} = \code{D}*2^{\code{\scriptsize}S}$.
	\item{3.} Repeat \code{K} times:
	  \begin{description}
	    \item{a.} Pick a random integer, \code{A} with \code{1 < A < Q-1}.
	    \item{b.} Raise \code{A} to the \code{D}\textsuperscript{th} power, mod \code{Q}.
	      Let \code{\codescript{B}{0}{} = mpow(A, D, Q)}.
	    \item{c.} If \code{\codescript{B}{0}{} == 1},
	      then continue with the next of the \code{K} iterations.
	    \item{d.} Otherwise, compute \code{\codescript{B}{0}{S} rem Q} by repeated squaring:
	      \begin{description}
		\item{i.} For \code{I} in \code{1} to \code{S}, let
		  \code{\codescript{B}{I}{} = (\codescript{B}{I-1}{} * \codescript{B}{I-1}{}) rem Q}.
		  Remark:
		  \begin{math}
		    \code{B}_{\scriptsize{\code{I}}} =
		    \code{B}_{\scriptsize{\code{0}}}^{\left(\scriptsize{\code{2}}^{\tiny{\code{I}}}\right)}
		  \end{math}

		  \code{\codescript{B}{I}{} == \codescript{B}{0}{2\textsuperscript{I}} rem Q}.
		\item{ii.} If for any \code{I} in \code{1} to \code{S}, \code{\codescript{B}{I}{} == 1}
		  and \codescript{B}{I-1}{} is neither \code{1} nor \code{Q-1},
		  then return false.
		  \code{Q} has failed the square-root test and is not prime.
		\item{iii.} If \code{\codescript{B}{S}{} /= 1} then return \code{false}.
		  \code{Q} has failed the Fermat test and is not prime.
		\item{iv.} If both conditions hold, then \code{Q} has passed this round of the
		  Rabin-Miller algorithm.
	      \end{description}
	  \end{description}
	\item{4.} If \code{Q} passes all \code{K} rounds, then the probability that \code{Q} is
	  composite is at most $4^{-\code{\scriptsize{K}}}$, and Rabin-Miller returns \code{true}.
	\item{5.} Otherwise (i.e.\ \code{Q} failed either the square-root test or the Fermat
	  test on one of the \code{K} rounds), Rabin-Miller returns \code{false}.
      \end{description}

\subsection{Details on Rabin-Miller}\label{sec:numb}
  My goal here is to take the ``magic'' out of the algorithm and keep everything simple and informal.
  Anyone who has taken MATH 312 or similar has probably seen all of these theorems before and may
  want to skip this section, especially if you're easily offended by informality.
  In the following, I will write $X \equivp Y$ to denote $(X \bmod P) = (Y \bmod P)$.

\subsubsection{Fermat's Little Theorem}\label{sec:flt}
  Not to be confused  with Fermat's Last Theorem which is much harder to prove.
  OTOH, the ``Little Theorem'' wins for being useful.
  \begin{quote}
    \emph{Fermat's Little Theorem:}
    If $P$ is prime, and $A$ is an integer that is not a multiple of $P$, then
    \begin{displaymath}\begin{array}{lrcl}
      A^{P-1} \equivp &=& 1
    \end{array}\end{displaymath}
  \end{quote}
  When reasoning about arithmetic $\bmod~P$, it is sufficient just to consider values in $\{0, \ldots, (P-1)\}$.
  If $A$ is such an integer, and $A$ is not a multiple of $P$, that just means that $A$ is in $\{1, \ldots, (P-1)\}$.
  Let $S_P$ be the set $\{1, \ldots, (P-1)\}$.
  \begin{enumerate}
    \item If $A \in S_P$, then for any integer $i \geq 0$, then $A^i \in S_P$.
      This is because $P$ is prime, and the product of any two positive integers that are less than $P$ cannot be
      a multiple of $P$.
    \item If $A \in S_P$, then all elements of the sequence $A^0 \bmod P,\ A^1 \bmod P,\; A^2 \bmod P, \ldots$
      must be elements of $S_P$.  By the pigeon-hole principle, there must be some value, $B$ that appears
      multple times in the sequence.  Choose $B$ to be the first such state (note: we could show $B = 1$, but
      that's slightly more work).  Let $C$ be the length of the cycle.  I.e.\ $C$ is the smallest integer
      such that $B \equivp B*A^C$.  Thus, $B, B*A \bmod P, B*A^2 \bmod P, \ldots, B*A^C \bmod P$ are a cycle.
    \item Now we show that $C$ must be a factor of $P-1$.  If $C = P-1$, then we're done.
      Otherwise, choose some element of $S_P$ that is not in the cycle, call it $D$.
      The sequence $D*A^0 \bmod P, D*A^1 \bmod P, \ldots D*A^C \bmod P$ must form a new cycle where
      no elements on this new cycle are elements of the original cycle.
      We can keep doing this until every element of $S_P$ is an element of one of these cycles;
      these cycles are all disjoint; and all cycles have length $C$.
      Thus, if $E \in S_P$, $E*A^C \equivp E$ which implies $A^C \equivp 1$.
    \item Let $F$ be the total number of cycles found above.  Because every element of $S_P$ is on exactly
      one cycle, $F*C = |S_P| = P-1$.  Therefore
      \begin{displaymath}
	A^{P-1} \equivp \left(A^C\right)^F \equivp 1^F = 1
      \end{displaymath}
      This completes the proof.
  \end{enumerate}
  %
  \noindent%
  \textbf{The Fermat Test -- some examples}\\
  If \code{Q} is an alleged prime, we'll can randomly choose some \code{A} in $\{2, \ldots, Q-1\}$
  and check if \code{mpow(A, Q-1, Q) == 1}.  We'll call this the \emph{Fermat-test}.
  For example, \code{11} is prime; and \code{5} is an integer that is not a multiple of \code{11};
  and the Fermat test yields:
  \begin{displaymath}\begin{array}{rcl}
    \code{mpow(5, 10, 11)} &=& \code{misc:mod(ipow(5, 10), 11)}\\
			   &=& \code{misc:mod(9765625, 11)}\\
			   &=& \code{misc:mod(887784*11 + 1, 11)}\\
			   &=& 1.
  \end{array}\end{displaymath}
   Most of the time, $A^{Q-1} \nequivq 1$ if $Q$ is not prime, for example,
   For example, \code{12} is not prime; \code{5} is an integer that is not a multiple of \code{12}; and
   \begin{displaymath}\begin{array}{rcl}
     \code{mpow(5, 11, 12)} &=& \code{misc:mod(ipow(5, 11), 12)}\\
			    &=& \code{misc:mod(48828125, 12)}\\
			    &=& \code{misc:mod(4069010*12 + 5, 12)}\\
			    &=& 5.
   \end{array}\end{displaymath}
   Thus, \code{12} fails the Fermat-test, and we have shown that \code{12} is not prime.

   Unfortunately, there are numbers called
   \hrefc{https://en.wikipedia.org/wiki/Fermat_pseudoprime}{Fermat pseudoprimes} that are composite,
   but pass the Fermat test for at least one choice of \code{A}.
   For example, \code{21} is not prime, \code{13} in an integer that is not a multiple of \code{21}, and
   \begin{displaymath}\begin{array}{rcl}
     \code{mpow(13, 20, 21)} &=& \code{misc:mod(ipow(13, 20), 21)}\\
			     &=& \code{misc:mod(19004963774880799438801, 21)}\\
			     &=& \code{misc:mod(904998274994323782800*21 + 1, 21)}\\
			     &=& 1.
   \end{array}\end{displaymath}
   In fact, there are pathological choices for \code{Q} where \code{Q} is composite and
   \code{mpow(A, (Q-1), Q) = 1} for all integers \code{A} that are not multiples of \code{Q}.
   Such numbers are called
   \hrefc{https://en.wikipedia.org/wiki/Carmichael_number}{Carmichael numbers}.
   561 is the smallest Carmichael number.

\subsubsection{The square-root of 1 ($\bmod~P$)}\label{sec:sqrt}
  \begin{quote}\it
    If $P$ is a prime and $A$ is an integer such that $A*A \bmod P = 1$,
    then either $A \bmod P = 1$ or $A \bmod P = P-1$.
  \end{quote}
  Proof.  Let $A$ be an integer such that $A*A \equivp 1$.
  \begin{displaymath}\begin{array}{rcll}
    A*A &\equivp& 1, & \textrm{given}\\
    A*A - 1 &\equivp& 0, & \textrm{subtract 1 from both sides}\\
    (A+1)*(A-1) &\equivp& 0, & \textrm{factoring}\\
  \end{array}\end{displaymath}
  If the product of integers $X$ and $Y$ is a multiple of a prime, at least one of
  $X$ or $Y$ must be a multiple of $P$.  Therefore, either $(A+1)$ or $(A-1)$ must be
  a multiple of $P$ which proves the claim.
  %
  \par\noindent%
  \textbf{The Square Test -- some examples}\\
  The contrapositive of the observation that we made above is that if we can
  find an integer $A$ such that $A \nequivq 1$, $A \nequivq Q-1$, and $A*A \equivq = 1$,
  then $Q$ is not prime.  We call this the \emph{square-test}.

  As described in the Question~\ref{q:rabin-miller}, the Rabin-Miller algorithm factors
  \code{Q-1 = D*ipow(2, S)} and computes \code{mpow(A, Q-1, Q)} by first computing
  \code{mpow(A, D, Q)} and squaring the result \code{S} times.  If they observe a value, \code{X},
  such that $\code{X} \nequivq  1$, $\code{X} \nequivq (\code{Q}-1)$, and  $\code{X*X} \equivq 1$,
  then by the square-test, \code{Q} is not a prime.
  OTOH, if after squaring \code{S} times, they don't reach \code{1}, then by the Fermat-test,
  \code{Q} is not prime.
  The proof that this fails with a probability of at most $\frac{1}{4}$ and that trials are
  independent for independently chosen values of \code{A} is beyond the scope of this description.

  Going back to our previous example of showing that \code{21} passes the Fermat test when
  \code{A=13}.  For the Rabin-Miller test:
   \begin{displaymath}\begin{array}{rcl}
     \code{Q}                &=& 21\\
     \code{Q-1}              &=& 20\\
     \code{D}                &=& 5\\
     \code{S}                &=& 2\\
     \code{A}                &=& 13\\
     \code{mpow(13, 5, 21)}  &=& 13\\
     \code{misc:mod(13*13, 21)} &=& 1
   \end{array}\end{displaymath}
   The square-test fails, and Rabin-Miller refutes the primality of \code{21}.

\textbf{Guards}: in general, guards are a good idea.
If you use guards, then your code will tend to fail close to the actual error, and
that makes debugging easier.
Guards also make your intentions and assumptions part of the code.
Documenting your assumptions in this way makes it much easier if someone else needs
to work with your code, or if you need to work with your code a few months or a few
years after you originally wrote it.
There are some cases where adding guards would cause the code to run much slower.
In those cases, it can be reasonable to use comments instead of guards.
Here are a few rules for adding guards:
\begin{itemize}
  \item If you need the guard to write easy-to-read patterns, use the guard.
    For example, to have separate cases for \code{N > 0} and \code{N < 0}.
  \item If adding the guard makes your code easier to read (and doesn't have a
    significant run-time penalty), use the guard.
  \item If a function is an ``entry point'' into your code (e.g.\ an exported function)
    it's good to have your assumptions about arguments clearly stated.  Ideally, you
    this with guards, that is great.  
    \begin{itemize}
      \item Often, a function can only be implemented for \emph{some} values of its arguments.
	For example, we might have:
	\begin{SmallCode}
	  sendSquare(Pid, N) -> Pid ! N*N.
	\end{SmallCode}
	A call such as \code{SendSquare([1, 2, 3], cow)} doesn't make sense.
	Bad calls should throw an error (e.g.\ a \code{badarg} error).
	Please, don't silently ignore bad arguments, for example
	\begin{SmallCode}
	  sendSquare(Pid, N) ->\\
	  \> if \=is\_pid(Pid) and is\_number(N) -> Pid~!~\tuple{square, N*N};\\
	  \>    \>true -> "messed up actual arguments" \xcomment{\textcolor{red}{Don't do this.}}\\
	  \> end\\
	  end.
	\end{SmallCode}
	The caller might very well ignore the return value of \code{SendSquare}, and
	\code{Pid} might end up blocking, waiting for a message that will never arrive.
	Furthermore, putting tests to see if the return value is an error code is so C,
	but throwing explicit exceptions and writing error handlers (if you want to do
	something other than killing the process that threw the error) is so much easier
	to write, read, and maintain.
	\par
	We will test your code on bad arguments and make sure that an error gets thrown.
    \end{itemize}
  \item Adding lots of little guards to every helper function can clutter your code.
    Write the code that you would want others to write if you are going to read it.
  \item In some cases, guards can cause a severe performance penalty.
    In that case, it's better to use a wrapper function so you can test the guards once
    and then go on from there. Or you can use comments; comments don't slow down the code.
    Any exported function should throw an error when called with bad arguments.
\end{itemize}


A common case for omitting guards occurs with tail-recursive functions.
We often write a wrapper function that initializes the ``accumulator'' and
then calls the tail-recursive code.
We export the wrapper, but the tail-recursive part is not exported because
the user doesn't need to know the details of the tail-recursive implementation.
In this case, it makes sense to declare the guards for the wrapper function.
If those guarantee the guards for the tail-recursive code, and the tail
recursive code can only be called from inside its module, then we can omit
the guards for the tail-recursive version.  This way, the guards get checked
once, but hold for all of the recursive calls.  Doing this gives us the
robustness of guard checking \textbf{and} the speed of tail recursion.\medskip
