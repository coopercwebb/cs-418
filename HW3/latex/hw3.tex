    \begin{enumerate}
      \item (\textbf{5 points})\label{q:tail.c3s}
	Consider our friend, the \code{count3s} function:
	\begin{xcode}
	  count3s([]) -> 0;\\
	  count3s([3 | Tl]) -> 1 + count3s(Tl);\\
	  count3s([\_ | Tl]) -> count3s(Tl);
	\end{xcode}
	Is \code{count3s} tail-recursive?\\
	Why or why not? \\
    \begin{answer}
      No, by definition a tail-recursive function is one where the the recursive call 
      is the last statement that is executed by the function\textsuperscript{{\hyperlink{ref1}{1}}}.
      Here each intermediate stack frame must wait to add 1 to the recursive call. Therefore, the recursive 
      call is not the last statement executed by the function.
    \end{answer}

	if your answer to Question~\ref{q:tail.c3s} was ``Is not tail-recursive'', and that is

    \begin{answer}

    \end{answer}

    \begin{answer}
      No, function calls must wait for the return of recursive calls to perform additional work (ie. message passing).

      \item (\textbf{2 points})
	Is the function \code{stat/3} in Figure~\ref{fig:hw2-fun} tail-recursive?
	Give a one-sentence justification for your answer. \\
    \begin{answer}
      Yes, as the final statement executed by the function is a recursive call.
    \end{answer}
      \item (\textbf{3 points})
	Name two advantages of using tail-recursive functions.
	At least one of these should be specific to implementing message-passing programs. \\
      \begin{answer}
      Advantage 1 - Memory Efficiency: As tail-recursive functions last executed statement is a recursive call,
      stack frames can be re-used for the recursive call (tail call elimination). Improving performance by reducing space complexity.
      \\
      Advantage 2 - Message-Passing Servers: Tail-recursive functions allow message-passing servers to run indefinitely without consuming stack space, as each recursive call to handle the next message reuses the same stack frame.
      \end{answer}
      \item (\textbf{3 points})
	Give a one or two sentence explanation of where it can be a better choice to implement
	a recursive function without using tail-recursion. \\
      \begin{answer}
        When intermediate results from each recursive call need to be combined or processed on the return path, non-tail-recursion is preferred because it maintains the call stack to preserve these intermediate values. Examples include tree traversals that aggregate data or mathematical functions that combine results from subproblems.
      \end{answer}

  \item \textbf{Message Passing Networks}
    \begin{enumerate}
      \item Bisection Width of a Fat Tree (\textbf{15 points})\\
	Fat-trees
	(see slide 20 of the \hrefc{https://www.students.cs.ubc.ca/~cs-418/2025-1/lecture/09-26/slides.pdf}{Sept.\ 26 lecture slides}) are a generalization of tree interconnect that avoid the
	bandwidth bottleneck at the root by using an increasing number of links between
	tree notes when going up in the tree.  In particular, if a node is the root of
	a subtree with $M$ nodes, then there will be $\lceil M^\alpha \rceil$ links from
	the node to its parent, with $0 \leq \alpha \leq 1$ being a design paramter.
	Fat trees have been used in real super-computers.
	For example, the
	\hrefc{https://en.wikipedia.org/wiki/Tianhe-2}{Tianhe-2 supercomputer} held
	the fastest supercomputer position on the
	\hrefc{https://www.top500.org}{Top-500 supercomputer list} for three years
	from June 2013 to June 2016 when it was superceded by the Sunway TaihuLight
	computer.  The Tianhe-2 used a fat-tree for its interconnect, see
	\hrefc{https://dx.doi.org/10.1007/s11390-015-1520-7}{High Performance Interconnect for Tianhe System} -- here is the UBC ez-proxy \hrefc{https://link-springer-com.ezproxy.library.ubc.ca/content/pdf/10.1007/s11390-015-1520-7.pdf}{link}.
	\par
	\begin{enumerate}
	  \item (\textbf{5 points})
	    What is the bisection width of a Fat Tree with $2^k$ leaves?
	    Give a formula in terms $k$ and $\alpha$.\\
	    You can assume that the router-nodes are huge crossbars
	    (see the paper citedwabove if you want the details of how it can be done
	    in practice, but we won't complicate this question with more detail).
	    You don't need to ``look-inside'' the router-nodes to answer this question. \\
      \begin{answer}
        $\lceil (2^k - 1)^{\alpha} \rceil$ \\
        (Cutting one root branch based on the formula above, 2L - 1 nodes in a tree (half of the leaves are present))
      \end{answer}
      
	  \item (\textbf{10 points})
	    Give a short justification of your answer.  For example:
	    \begin{itemize}
	      \item Point out that if the minimum bisection involves cutting one
		link between two nodes, it must involve cutting all links between
		those nodes.  If you use this in your justification, give a one
		sentence justification.
	      \item State which links are cut to get the minimum bisection.
	      \item Give a short explantion of why this is the minimum cut.
		Short means no more than three sentences. \\
        \begin{answer}
          Based on the bisection width of a standard tree ``For tree topology with n nodes can be bisected at the root by breaking one link, so bisection bandwidth is one link bandwidth''\textsuperscript{{\hyperlink{ref2}{2}}}, the same logic applies to the fat tree.
          However, in a fat tree with $2^k$ leaves, this "one link" between the root and a child subtree (containing $2^k - 1$ total nodes) actually consists of $\lceil (2^k - 1)^{\alpha} \rceil$ parallel links.
          All of these parallel links must be cut to achieve bisection, because otherwise the two halves would still be connected.
          Therefore, the bisection width is $\lceil (2^k - 1)^{\alpha} \rceil$.
        \end{answer}
	    \end{itemize}
	\end{enumerate}

  \item \textbf{Communication Overhead} (\textbf{25 points})\\
    Consider the problem of computing the sum of the elements of a list, \code{List},
    of \code{N} elements that is distributed across \code{NW} workers.
    Each worker has a segment with \code{N/NW} elements of \code{List}.
    For simplicity, we will assume that  \code{N} is a multiple of \code{NW}, and
    that \code{NW} is a power of two.
    \par
    Of course, we will use reduce to compute the sum.
    The worker tasks will use \code{lists:sum} to compute their sums.
    Assume that \code{lists:sum(L)} takes time $3\mathrm{ns}*\code{length(L)}$
    where ns is short for ``nanosecond'', and one nanosecond is $10^{-9}$ seconds.
    Assume that sending one integer between processes takes $2\mu\mathrm{s}$
    where $\mu\mathrm{s}$ is short for ``microsecond'',  and one microsecond is $10^{-6}$ seconds.
    This is the total time for from when when the sending process starts the send until the
    receiving process completes the receive.
    \begin{enumerate}
      \item (\textbf{4 points}) What is the time to compute the sum using reduce?\\
	Note that reduce makes two passes through the tree, one bottom-up and the other top-down
	whether we use \code{wtree:reduce} or the book's method.  So, your answer should
	be the same for either method.  We are ignoring compute-time for non-leaf nodes of
	the tree because it is negigible compared with the communication time. \\
  \begin{answer}
    Leafs are computed in parallel. Communication is done in parallel so it is equal to the height of the tree times 2 (reduce up and reduce down). \\
    $3ns\cdot(N/NW) + 2(2\mu s \cdot 1000ns/\mu s \cdot log_2NW)$ \\
    = $3ns\cdot(N/NW) + 4000ns \cdot log_2NW$ 
  \end{answer}
      \item (\textbf{4 points}) What is the time to compute the sum sequentially,
	i.e.\ using a single process? \\
      \begin{answer}
        $3ns \cdot N$
      \end{answer}
      \item (\textbf{4 points}) What is the speed-up? \\
      \begin{answer}
        $\frac{3 \cdot N}{3\cdot(N/NW) + 4000 \cdot log_2NW}$
      \end{answer}
      \item (\textbf{3 points}) What is the speed-up if \code{N=100,000} and \code{NW=16}? \\
      \begin{answer}
        $\frac{1200}{139} \approx 8.633$
      \end{answer}
      \item (\textbf{6 points})
	Now consider an implementation in C.
	Assume that C is $10\times$ faster for computing the sum of the elements of an array.
	In other words, the time to compute the sum of an array with \code{N} elements
	is $0.3\mathrm{ns} * \code{N}$.
	Assume that communication costs are the same as the Erlang case (similar costs
	for any OS overhead, thread synchronization, etc.).
	\par
	For the questions below, we have given you space to show two or three
	lines of work for each answer.
	\begin{enumerate}
	  \item What is the parallel  time for the C implementation
	    with \code{N=100,000} and \code{NW=16}? \\
    \begin{answer}
    Leafs are computed in parallel. Communication is done in parallel so it is equal to the height of the tree times 2 (reduce up and reduce down). \\
      $0.3ns \cdot(N/NW) + 2(2\mu s \cdot log_2NW)$ \\
      =  $0.3ns \cdot \frac{1 \mu s}{1000 ns} \cdot(N/NW) + 4\mu s \cdot log_2NW$ \\
      = $17.875 \mu s$
    \end{answer}
	  \item What is the sequential time for the C implementation
	    with \code{N=100,000}? \\
    \begin{answer}
      $100000 \cdot 0.3ns \cdot \frac{1\mu s}{1000ns}=30 \mu s$
    \end{answer}
	  \item What is the speed-up for the C implementation
	    with \code{N=100,000} and \code{NW=16}? \\
    \begin{answer}
      $\frac{0.3 \cdot N}{0.3\cdot(N/NW) + 4000 \cdot log_2NW} = 1.67832$
    \end{answer}
	  \item Which is fastest, the Erlang sequential, Erlang parallel, C sequential,
	    of C parallel?\\
    \begin{answer}
      C parallel.
    \end{answer}
	  \item Which gets the greater speed up,
	    Erlang parallel vs.\ Erlang sequential,
	    or C parallel vs.\ C sequential? \\
    \begin{answer}
      Erlang parallel vs. Erlang sequential.
    \end{answer}
	  \item Give a one or two sentence explanation for the relationship you observe
	    about which is fastest and which gets the greater speed-up. \\
    \begin{answer}
      The C parallel version is fastest because even though its speed-up is less than the Erlang implementation, the communication overhead is equal and the parallel summing portions execute faster. The Erlang parallel vs. Erlang sequential experiences greater speed-up because we are dealing with a relatively small problem size (N=100,000) where the serializable portion (communication overhead) represents a significant cost, but as you approach infinitely large problem sizes, this serializable portion becomes infinitesimally small compared to the parallel portion, and both speed-ups would approach NW (16 in this case).
    \end{answer}
	\end{enumerate}
